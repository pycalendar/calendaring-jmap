``get_availability`` no longer silently returns the wrong account's busy intervals when asked about more than one account. ``Principal/getAvailability`` has no ``accountId`` argument, so it can only ever report on the account you are authenticated as; any other account id in the request now always goes through the ``CalendarEvent/query`` fallback, which does scope to an explicit account, instead of returning the same primary account's data twice under different keys.
