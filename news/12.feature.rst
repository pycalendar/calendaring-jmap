Added scheduling: ``accept_invitation``, ``decline_invitation``, ``tentatively_accept``, and ``send_invite`` on both ``JMAPClient`` and ``AsyncJMAPClient``. The three response methods take the event id and your own email address, find the matching participant on the live event, and patch just that participant's ``participationStatus``. ``send_invite`` is ``create_event`` with the server told to actually dispatch invitations. ``build_event_set_create``/``build_event_set_update``/``build_event_set_destroy`` gained a ``send_scheduling_messages`` argument for this; ``delete_event`` also gained it, so cancelling an event can send participants an iTIP CANCEL. ``get_event`` gained the same ``account_id`` parameter the other event methods already had, since responding to an invitation on a shared calendar needs it.
