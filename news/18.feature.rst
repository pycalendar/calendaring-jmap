Added ``get_task_sync_token``, ``get_tasks_by_sync_token``, and ``search_tasks`` to both ``JMAPClient`` and ``AsyncJMAPClient``. ``search_tasks``'s ``due_before``, ``due_after``, and ``progress`` filters have no matching ``Task/query`` filter property (the draft spec never defines one), so they filter client-side against the tasks the server's ``text`` filter already matched, not on the server. ``search_tasks`` falls back to fetching every task and filtering everything client-side, including ``text``, when the server doesn't support ``Task/query`` at all.
