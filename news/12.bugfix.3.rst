``ical_to_jscal`` no longer writes a non-mailto ORGANIZER/ATTENDEE URI (e.g. ``sip:alice@example.com``) into the Participant ``email`` property, which RFC 8984 defines as an RFC 5322 addr-spec, not an arbitrary URI. Such a participant now has ``calendarAddress`` only, no ``email``, and accepting/declining an invitation for it works correctly via a ``calendarAddress`` match. ``jscal_to_ical`` no longer double-wraps a non-mailto ``calendarAddress`` in a spurious ``mailto:`` prefix on the way back to iCalendar. ``_find_participant_id_by_email`` no longer crashes with an ``AttributeError`` when a participant has an explicitly null ``calendarAddress``.
