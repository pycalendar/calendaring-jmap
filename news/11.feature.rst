Added calendar management: ``create_calendar``, ``update_calendar``, ``delete_calendar``, ``share_calendar``, ``get_calendar_subscriptions``, and ``set_default_alerts`` on both ``JMAPClient`` and ``AsyncJMAPClient``. ``JMAPCalendar`` gained ``time_zone``, ``share_with``, ``default_alerts_with_time``, and ``default_alerts_without_time`` fields.

``delete_calendar`` takes an ``on_destroy_remove_events`` flag: deleting a calendar that still has events raises ``calendarHasEvent`` unless it is set. ``set_default_alerts`` takes ``alerts_with_time``/``alerts_without_time`` separately, since the JMAP Calendars spec defines them as two independent Calendar properties with no natural single-dict merge.

``get_calendars`` takes an ``account_id`` to browse a calendar another user has shared with you. ``create_event``, ``update_event``, ``delete_event``, ``search_events``, ``update_calendar``, ``delete_calendar``, and ``set_default_alerts`` all gained the same ``account_id`` parameter so they can target that shared calendar's owning account instead of always using your own; ``share_calendar`` gained the equivalent ``owning_account_id`` (its own ``account_id`` parameter already means the account you are sharing with). ``JMAPCalendar.search()``, ``add_event()``, and ``get_object_by_uid()``, along with ``JMAPCalendarObject.save()``, now route through the calendar's owning account automatically once it was fetched via ``get_calendars(account_id=...)``.
